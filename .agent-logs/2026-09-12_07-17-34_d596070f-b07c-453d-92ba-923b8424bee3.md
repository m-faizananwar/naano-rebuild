## 1. Data model

All tables `id, created_at, updated_at`; money in EUR cents.

- **users** (email, password_hash, role, names) · **sessions** (token_hash, expires_at)
- **brands** (owner, company, website, value_prop, icps[3], target_industries[], target_regions[], wallet_cents, pixel_site_key)
- **creators** (user, linkedin_url, headline, bio, country, industries ≤3, followers, price_cents, bundles[], median_views, engagement_rate, posts_per_month, audience_job_titles{}, audience_seniority{})
- **campaigns** (brand, name, status, open_to_applications, post_deadline, default_fee_cents, brief jsonb in the editor's exact shape: what_to_tell, target_industries, target_geos, tone, do[], avoid[], links[], angles[{angle, hook, direction, example}])
- **collaborations** (campaign, creator, origin `invitation|application`, status, fee_cents, due_date, revision_round, draft_text, post_url, scheduled_at, published_at, paid_at) — unique (campaign, creator)
- **collaboration_events** (from, to, actor, note) — written by every `transition()`; the audit trail
- **tracking_links** (collaboration, code unique+indexed, destination) · **clicks** (link, ts, ip_hash, ua, referrer)
- **pixel_events** (site_key, `visit|signup|purchase`, value_cents, click nullable) · **ledger** (party, `topup|booking|payout|withdrawal`, amount, collaboration) — wallet, earnings, invoices are views over it · **shortlist** · **messages**

`fitScore` is computed, never stored: audience overlap, category match, engagement quality, posting consistency — each a signal with a one-line reason.

**State machine** (only transitions the map shows):

| from | to | who |
|---|---|---|
| — | `invited` | brand |
| — | `applied` | creator |
| `invited` | `accepted` / `declined` | creator |
| `applied` | `accepted` / `declined` | brand |
| `accepted` | `draft_submitted` | creator ("Draft ready") |
| `draft_submitted` | `approved` / `changes_requested` | brand (the review modal: "approving or requesting changes", bounded by revision rounds) |
| `changes_requested` | `draft_submitted` | creator |
| `approved` | `scheduled` | creator (sets date) |
| `scheduled` | `live` | creator (post URL — self-reported, no LinkedIn API) |
| `live` | `paid` | system when the wallet covers it; brand "Pay" if short |

Terminal: `declined`, `paid`. Tabs map directly (brand "Invitations received" = `applied`, creator "Needs action" = `invited ∪ changes_requested ∪ approved`). Not modelled because not in the map: cancel after acceptance, disputes, refunds.
